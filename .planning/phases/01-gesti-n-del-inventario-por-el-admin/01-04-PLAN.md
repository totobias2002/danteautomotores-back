<objective>
Cerrar la mitad de "formato uniforme" de PROD-01: un solo `@RestControllerAdvice` que extiende `ResponseEntityExceptionHandler` y devuelve `{"error": "..."}` en español para errores de negocio, de framework y genéricos, sin filtrar detalles internos. Se hace con TDD porque el contrato tiene entradas y salidas claras: excepción → status + cuerpo.

Objetivo de la fase (ROADMAP, textual; no está en formato de user story): "La única cuenta admin gestiona el inventario completo de autos (datos, fotos, estado y destacados) desde el panel, contra la API real y con errores manejados de forma uniforme".

Purpose: hoy un type mismatch devuelve "For input string: "abc"" en inglés, una excepción no controlada devuelve el 500 por defecto de Spring y la validación devuelve un mapa plano sin `error`. Con este contrato, el helper `mensajeDeError` de 01-01 muestra siempre un texto útil en los forms. También define `ServicioExternoException` → 502, que 01-06 usa para envolver los errores de Cloudinary.
Output: test de contrato `GlobalExceptionHandlerTest` (RED), `GlobalExceptionHandler` reescrito y `ServicioExternoException` (GREEN).

Decisión de compatibilidad (discreción de CONTEXT): el formato de validación pasa de `{"campo": "msg"}` a `{"error": "Datos inválidos", "campos": {...}}`. Ningún consumidor actual lee el mapa plano (los forms del front mostraban textos genéricos), así que no hace falta mantener el formato viejo.
</objective>
