<objective>
Tracer de la fase: el admin abre el panel y ve TODOS sus autos (todos los estados) a través de un endpoint exclusivo de admin, atravesando de punta a punta las capas que la fase modifica (SecurityConfig → filtro JWT → controller → service → repository → front). Sobre ese corte se agrega el manejo de la parte de seguridad de PROD-01: tokens malos dan 401 JSON (nunca 500), rol insuficiente da 403 JSON, y el front lleva al login con aviso de "sesión vencida" y vuelve a la página de origen.

Objetivo de la fase (ROADMAP, textual; no está en formato de user story, ver nota en el resumen de planificación): "La única cuenta admin gestiona el inventario completo de autos (datos, fotos, estado y destacados) desde el panel, contra la API real y con errores manejados de forma uniforme".

Purpose: hoy el panel trae solo `DISPONIBLE` (un auto reservado desaparece) y un token vencido rompe el panel con 500 (RESEARCH Pitfall 1). Este plan prueba la arquitectura (matcher `/api/admin/**`, handlers de Security, interceptor axios) antes de expandir.
Output: endpoint `GET /api/admin/publicaciones`, `RestAuthenticationEntryPoint`, `RestAccessDeniedHandler`, filtro JWT que nunca lanza, base de tests `SeguridadWebMvcTestBase`, helper `mensajeDeError`, interceptor 401 y redirección con vuelta al origen.
</objective>
